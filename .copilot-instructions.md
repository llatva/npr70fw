# Copilot Guidance for NPR-70 FreeRTOS Port

## Purpose
This repository uses two linked status documents:

- `PORTING_STATUS.md` — overall port progress, completed components, current risks, and testing readiness.
- `PORTING_TODO.md` — the active work backlog and remaining implementation tasks.

## Rule
Whenever any item is completed from `PORTING_TODO.md`, update both documents.

### `PORTING_TODO.md`
- mark the item as completed or remove it if no longer relevant.
- update dependent tasks or priorities if needed.

### `PORTING_STATUS.md`
- reflect the completion in at least one of these sections:
  - component status summary
  - functional implementation status
  - completed items since last report
  - testing requirements
- if the change is significant, update the overall status and date.

## Why
These files are maintained together so reviewers and developers can see both:
- what remains to be done, and
- what has already been completed.

## Best Practice
- Do not finalize a task in `PORTING_TODO.md` without also adjusting `PORTING_STATUS.md`.
- Keep both files consistent in wording and status markers.
- Use the same TODO numbering and component names when possible.
- When marking work complete, add the completion date or version if practical.
- Keep TODO items small, actionable, and limited to one change per item.
- Link each TODO to the exact file(s) or code area it affects.
- Update `PORTING_STATUS.md` before or together with code changes so status stays current.
- Use clear status language: `✅ Complete`, `⚠️ Partial`, `🔴 Blocked`, `❌ Missing`.
- Avoid moving items silently; if a task changes scope, note it in both files.
- Commit `PORTING_STATUS.md` and `PORTING_TODO.md` together in the same change when possible.
